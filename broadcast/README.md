# Odeum — YouTube Live 番組制作

VANMAC (macOS) を親機にする遠隔4入力と番組返送の設定は [VANMAC.md](VANMAC.md) を参照。
以下の既存プロファイルは Windows/NVENC 用。Macへそのまま配置しない。

最大4本の入力をOBSで切替・合成し、1本の番組としてYouTube Liveへ送る。
入力機材とYouTubeチャンネルの接続は別途必要。これは接続前の設定一式であり、配信稼働済みではない。

## 構成

```text
入力1〜4（画面・カメラ・遠隔映像）
  → OBSの入力用シーン（各入力を一度だけ取り込む）
  → 全画面への切替 / 4分割 / 待機 / 終了
  → H.264 + AAC を1番組分だけ符号化
  → RTMPS → YouTube Live → 視聴者
```

100人への配信はYouTubeが分配する。制作PCは視聴者ごとに符号化・送信しない。
合成には復号・描画・出力符号化が必要で、全区間を無再符号化にはできない。
2026-10-04のDiscord調査の「再符号化・複製を必要箇所に限定する」方針を採用した。
MoQは今回は使用しない。YouTubeへは同社が提供するRTMPS入力で接続する。
既存の `odeum-relay` / `odeum-presenter` は1発表者のWebRTC配信用で、OBSのSRT入力と直接接続できない。

## ファイルと導入

- `obs/Odeum_YouTube_Program.json`: シーンコレクション。
- `obs/profile/`: 出力プロファイル。秘密情報・ストリームキーは含まない。

Windows / OBS 32.0.4を基準に作成。NVENC H.264が使えるNVIDIA GPUを前提とする。
別GPUを使う場合はOBSの設定から使用可能なエンコーダを明示的に選び直す。

OBSを終了した状態で、コレクションを `%APPDATA%/obs-studio/basic/scenes/Odeum_YouTube_Program.json`、
profile内の3ファイルを新規フォルダ `%APPDATA%/obs-studio/basic/profiles/Odeum_YouTube_1080p30/` に配置する。
既存の同名設定がある場合は上書きしない。特に運用済み `service.json` をテンプレートで置き換えない。
元のプロファイル・コレクションには変更を加えず、OBSで両方を明示的に選ぶ。
コレクションはOBS「シーンコレクション → インポート」でも追加できる。

## 入力を割り当てる

`SOURCE 1`〜`SOURCE 4` は共有する入力用シーン。初期状態は「入力未接続」の表示だけ。
各SOURCEシーンに実入力ソースを追加し、1920×1080のキャンバスへ「画面に合わせる」で配置する。
映像・音声が接続できたら、そのSOURCEの未接続表示を非表示にする。
番組側の各全画面と4分割には同じSOURCEシーンが反映される。取り込みソースを番組ごとに複製しない。

| 入力 | OBSのソース | 接続に必要な情報 |
| --- | --- | --- |
| 同じPCのアプリ | ウィンドウキャプチャ / ゲームキャプチャ | 対象ウィンドウ |
| カメラ・HDMI取り込み | 映像キャプチャデバイス | 接続済みデバイス、音声経路 |
| 別PCからSRT | メディアソース（ローカルファイルOFF、形式 `mpegts`） | 実際の送信元、caller/listener、許可された接続先とポート |

SRTは調査済み候補の1つ。遠隔入力を選んだ場合に設定する。未割当ポート・架空のURLは設定しない。
受信を維持する必要があるSRTソースでは「非アクティブ時にファイルを閉じる」をOFFにする。
SRTの遅延は回線のRTT・損失に合わせる。OBSのURLパラメータ `latency` の単位はマイクロ秒。
遠隔入力は個別の音ずれをOBSの同期オフセットで合わせる。再接続後も確認する。

## 音声

初期コレクションにはマイク・デスクトップ音声を割り当てていない。
`AUDIO - Program` シーンに実際の番組音声ソースを追加する。このシーンは全画面と4分割で共有する。
待機・終了には番組音声を含めない。各入力由来の音声と番組音声を二重に拾わないこと。
4分割で全入力の音が不要な場合は、不要な入力音声をミュートする。
マイクの機材、配信に必要な入力音声、モニター出力は接続時に確定する。

## 出力とYouTube接続

- 1920×1080 / 30fps、H.264 NVENC、CBR 10 Mbps、キーフレーム2秒、Bフレーム2。
- P5、単一パス、lookahead OFF。多重パスの追加GPU負荷を避ける初期設定。
- AAC 128 kbps、48 kHz、ステレオ、トラック1。
- 映像10 Mbpsに音声・通信分と余裕を加えた安定した上り帯域が必要。
- 同時録画を行うならMKV、配信エンコーダ共有。初期状態で録画は開始しない。

OBSの「設定 → 配信」でYouTubeの使用チャンネルを接続するか、同チャンネルのストリームキーを設定する。
キー・OAuthトークンをGitやチャットへ貼らない。テンプレートのキーは空であり、このままでは配信できない。
YouTube側の番組タイトル、公開範囲、遅延モードを確認する。
初回の確認配信は限定公開で、入力ごとの映像・音声、切替、4分割、A/V同期、ドロップを確認する。
シーンを終了画面へ変えるだけでは配信は停止しない。最後にOBSとYouTube側の配信終了を確認する。

## 受入条件と未実施の確認

1. 専用プロファイル・コレクションを選べる。元の設定を保持する。
2. 実入力を1〜4本割り当て、各全画面と4分割へ反映される。
3. 同じ音声が二重に出ず、待機・終了で意図しない音声が出ない。
4. YouTubeの限定公開で1番組として視聴できる。切替・同期・負荷を確認する。

設定ファイルの構造確認と、OBS起動・実機動作・YouTubeへの送出確認は区別する。
本変更ではOBS起動・実入力・エンコード・YouTube配信の動作確認を実施していない。
入力機材・チャンネルの指定と、起動・確認配信の指示を受けてから実施する。

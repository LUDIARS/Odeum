# Odeum AI 授業 (`odeum-lesson`)

AI が進行する授業を Odeum の上で行うためのサービス。授業の著者が書いた **プロット** から、進行表 (タイムライン)・
予習シート (pptx)・授業中の問いかけ・課題の見守り・質問の共有までを一つのデータから作る。
映像と音声の配信は既存の `odeum-presenter` → `odeum-relay` が受け持ち、`odeum-lesson` は授業の進行と
生徒とのやり取り (回答・課題・質問・発話) を受け持つ。

- 置き場所: `native/lesson/` (C++20、`odeum_protocol`・`odeum_relay_state`・Boost.Beast を利用)
- サンプル教材: `native/lesson/courses/action-game.plot.json`「アクションゲームの作り方」(Ergo Studio、90 分)。
  参考実装は <https://github.com/vtn-team/ActionGameSample> (Unity)。その演出 6 つ (`Setting` の切り替え: ヒットストップ・
  ノックバック・カメラの揺れ・ヒットエフェクト・ダメージの数字・体力ゲージの演出) を抜いた状態を考えさせ、何が足りないかを当てさせる。
  実演と課題は Ergo の**ヘッドレスのサンプル** `examples/lesson_action_feel` (遊べるゲームではなく、演出 3 つを ON / OFF して
  実際に起きたことをログと変数に出すシミュレーション。下の「道具との連携」) で行う。教材の記述はこの前提に合わせてある
  (遊ぶ手順は無く、数値の変わり方を見る)。

## 誰が何をするか

| 立場 | 画面 | できること |
| --- | --- | --- |
| 生徒 | `GET /lesson` (参加コード + 表示名、ログイン不要) | 先生の言葉とスライドを見る、問いに答える、課題のチェック、ヒントを求める、質問する、声で話す |
| 操作者 (人間の先生) | `GET /console` (この機械の loopback のみ) | 開講、進行の開始・停止・移動 (セクションの頭、またはタイムラインの合図「この合図まで進める」)、問いを出す・締める・結果を見せる、課題を出す、発言停止・退出、質問への回答・共有・見送り |
| 講師モデル | `LessonModel` (C++ interface) | 語り、採点、発話の読み取り、質問の評価と回答、ヒント |

**講師モデルは未着のため仮実装** (`make_provisional_model()`、名前 `provisional-rules`)。プロットに書かれた採点観点・ヒント・FAQ を
キーワードで引くだけで、プロットに無い内容は作らない。本物のモデルが届いたら `LessonModel` を実装して差し替える
(`native/lesson/core/model.hpp`)。教室の制御の流れは変わらない。

## プロットからタイムラインを起こす

プロット (JSON) は授業全体の時間、ゴール、準備、用語、FAQ と、セクションの並びを持つ。セクションは
語りの要点 (`points`)、実演の切替 (`demos`)、問い (`activity`)、課題 (`assignment`)、予習の問い (`prep`) を持てる。
実演は `note` (先生がすること、300 字) と `watch` (生徒が見るところ、任意、200 字) を持ち、生徒のページには
「先生の画面 (配信・教室のスクリーン) で実演中: <note> (ON/OFF)。見るところ: <watch>」と出る。映像は埋め込まない。
問いは任意の `explanation` (なぜその答えになるか、600 字) を持てる。結果を見せるときに全員に出し、予習シートには載せない。
`open` の問いには持たせられない (答えが無いので)。
道具 (Ergo Studio) と連携する教材は、実演の名前とゲームの変数の対応 (`tool.features`) と、課題の手順ごとの自動確認 (`check`) も書く
(下の「道具との連携」)。
FAQ の各項目は任意の `after` (問いの id) を持てる。その答えが授業のその問いの答えに触れるとき (後の問いを先回りして
明かしてしまうとき) に付け、その問いの結果を見せるまでは使わない (下の「答えを用意できない質問」)。
検証に通らないプロットは `invalid_plot` (どの項目かを添える)。

`build_timeline(plot, model)`:

- セクションの長さは `minutes` の比で授業時間 (`plot.minutes`) に割り付ける。
- セクション内は「語り → 問い (出す → 締める → 結果) → 課題」の順。語りの各行は文字数の比で時間を取り、
  少なくともセクションの 2 割は語りに残す。行ごとの持ち時間 (`seconds`) をモデルに渡す。
- 問いは回答時間 (`seconds`) の後に結果の説明 45 秒を取る。課題は 60 秒ごとに進み具合の確認を入れる。
- `share_questions: true` のセクションは終わりに良い質問の共有を入れる。

`TimelinePlayer` は外から渡された単調時計で進む (開始・一時停止・再開・位置指定・次のセクションへ)。
CLI: `odeum-lesson timeline <コース id | plot.json>` でタイムラインを JSON で出す。

## 予習シート (pptx)

`build_prep_sheet` → `write_pptx`。表紙・今日のゴール・準備・キーワード・予習の問い (セクションごと)・授業の流れ。
授業の流れの分数はタイムラインから取る。**問いの答え (模範解答・採点観点) は載せない。**
pptx は OOXML を直接書き、ZIP は無圧縮。時刻を埋め込まないので同じプロットからは同じバイト列になる。
取得: `GET /v1/prep.pptx?plot=<id>` または `odeum-lesson prep-sheet <コース id | plot.json> <出力.pptx>`。

## 授業中の問い (ClassPoint 風)

問いは生徒の端末に出て、結果を見せるまで他人の回答は見えない。生徒が回答欄から後で出した回答は前の回答を置き換える。

**発話と回答。** 「先生に話す」(文字・マイク) と教室のマイク (`voice.diarized`) の発話は、文字の問いが開いていて
**その生徒がまだ答えていない**ときだけ回答として受け取る。そのとき生徒には `answer.ack` (`via: "utterance"`, `answer: {text}`) を
送り、ページは「話した言葉を回答として受け取りました」と、その文を「いまのあなたの回答」として出す。すでに答えている生徒の
発話は回答を置き換えない (操作卓には `heard` の `intent: "remark"`、本人には `utterance.ack` の `kept_answer` と
「置き換えていません」の文)。`answer.ack` と `welcome` は、サーバが持っているその生徒の回答 (`answer`) を返し、ページはそれだけを
自分の回答として出す。

**話した言葉は必ず受け取り方を返す。** 「先生に話す」・マイク・教室のマイクの発話には、読み取りが何であっても本人に
`utterance.ack` (`taken_as`: `answer` / `remark` / `question` / `help` / `trouble` / `chatter` / `disruption`、`note`: どう扱ったかの文) を返す。
ページは「先生に話す」の下に、話した言葉の冒頭と `note` を次の発話まで出す (読み違いに本人が気づけるように)。
`trouble` は「デモの画面が小さくて見えなかった」「声が途切れて聞こえなかった」のような、授業そのものについていけないという知らせで、
質問ではない。仮モデルは「見えなかった・聞こえなかった・読めなかった・ついていけない…」と「デモ・画面・スライド・声・文字…」の
両方が出て、文が問いの形 (「？」「ですか」) で終わらないときにそう読む。質問ボードには載せず、操作卓に `heard` (`intent: "trouble"`) と
`attention` (`cannot_follow`、`report_id`) を出し、本人には「質問ボードには載せず、人間の先生に対応が要ると知らせた」と返す。
「質問する」から送られた同じ知らせも同じに扱う (本人へは `reply` の `about: "trouble"`)。

**知らせの行方。** 知らせは「知らせ」(`r1`…) として残る (質問とは別の小さな台帳 `core/reports.*`。票も共有も無い)。
操作卓は確認されていない知らせを、生徒の名前と本文つきで画面上部の帯「対応が要る知らせ」に出し続け、「確認した」
(`reports.ack {id}`) か「返事する」(`reports.reply {id, text}`) で外れる。返事はその生徒にだけ先生からの言葉 (`reply` の
`about: "report"`、`from: "teacher"`) として届く。生徒のページの「あなたの知らせ」には、サーバが送る状態 (`report.status`、
`welcome` の `my_reports`) を出す: `reported` (知らせました、先生の確認待ち) / `acknowledged` (先生が確認しました) / `replied`
(先生から返事、返事の文つき)。操作卓の `snapshot` は `reports` と確認されていない数 `reports_open` を持ち、「授業を閉じる」の確認にも
その数を出す。`lesson.end` の時点で誰も確認していない知らせは、その生徒に一度だけ「授業の時間内に先生が確認できなかった」と
挙げて伝える (`reply` の `about: "reports_unacknowledged"`)。退出した生徒の知らせは消す。

| 種類 | 内容 | 採点 |
| --- | --- | --- |
| `choice` | 選択肢 (単一 / 複数)。`correct` が空ならアンケート | 選んだ組が正解と一致 |
| `text` | 短い記述 | 採点観点のうち `min_points` 個以上に触れている |
| `missing` | 実装を抜いたコードを見せ、足りないものを挙げる | 同上 (観点 = 抜いた実装) |
| `open` | 正解のない問い (観点は意見の分類にだけ使う) | 判定しない。模範解答も持てない |

結果を見せるとき、全員にはクラスの集計 (選択肢ごとの数 / 観点ごとの数)・模範解答・名前を伏せた代表的な回答を、
各生徒には自分の回答 (`text` / `choices`) とそれへの一言を個別に送る。一言は規則で言えることだけを言う
(当てはまった観点、`min_points` に届いたか、ほかの観点)。「ほかの人からは…という観点も出ています」は、自分以外の誰かの回答が
実際に当てはまった観点だけで、誰も挙げていなければ言わない。理由の良し悪しのような、キーワードで判定できないことは言わない。
選択式の一言は「正解です。」/「正解とは違いました。」と、解説があればそれを見るように促す。

**キーワードの当て方** (仮モデル、`core/text.cpp`): 比較の前に全角英数を半角・小文字に、半角カナを全角に (濁点・半濁点も)、
カタカナをひらがなにそろえ、空白と記号を除く。辞書形のキーワード (「見える」「広く」「下がる」) は活用した形
(「見えない」「広めに」「下がった」) にも当たる: 最後のかなを落とし、残りが漢字で終わるときは、その語の活用で続きうるかな
(形容詞は い・く・か・け・さ・め・そ、動詞は同じ行と音便) が続くときだけ当てる (「広く」は「広告」に、「重い」は「重なる」に当たらない)。サンプル教材の主な問い:
「ヒットストップをどう設計するか」(`text`)、「ノックバックで何が起きるか」(`text`)、
「カメラはどうするのが良いか」(`open`、正解なし)。

## 課題の見守りと個別対応

課題は手順 (ステップ) の列。進み具合は生徒のチェック (`progress`)、生徒の機械の道具からの報告 (`POST /v1/tool/progress`、
下の「道具との連携」)、操作者の代理チェック (操作卓の `progress.report`) のどれかで入る。どの経路でも生徒のページに反映する。

- 出して 90 秒手を付けない → 最初の一歩を個別に促す。
- `stall_seconds` 進まない / 「ヒントがほしい」/ 声で助けを求めた → その生徒のいるステップのヒントを個別に出す。
  ヒントは段階的で、出し切ったら操作者に「直接見る」を通知し、自動のヒントは止める。
- 同じステップで 3 人以上かつ 4 割以上が止まった → 個別ではなく全員に一度だけ話す。
- 全部終えた → 褒めて、発展課題 (`extra`) を示す。
- ヒントを出し切ったときの文は「人間の先生に知らせた、先生から直接声がかかることがある」で、行くとは約束しない。
- 課題の最中に「質問する」から送られた文を仮モデルが「手が止まっている」知らせと読んだとき (「手順」「進まない」
  「反映されない」など、課題中だけ使う語) は、質問ボードに載せず、ヒントの経路 (上と同じ) に回し、本人にその旨を返す。
  操作卓には `heard` (`intent: "help"`) で本文が出る。
- 進み具合を受け付けられないとき (課題が終わった・別の課題) は、エラーではなく `progress.rejected` (`code` とサーバが持つ
  その生徒のチェック `assignment`、無ければ `null`) を返す。ページはチェックをそれに戻す。課題が終わるとチェック欄は押せなくなる。
- 生徒に送る課題の手順 (`assignment.steps[]`) には `auto` と、`check` がある手順はその条件 (`check: {variable, op, value}`) も
  付く。ページは「自動: 道具が <変数> > 0 を見たらチェック」と出す。
- 手順は任意の `how` (800 字) を持てる。その手順のやり方そのもの (そのまま打てるコマンド、読むファイルの場所) で、ページは手順の下に
  等幅でそのまま出す。サンプル教材の `how` のコマンドは、Ergo の実物 (Linux、libcurl 版のビルド) で書いたとおりに打って確かめてある。

## 道具との連携 (Ergo Studio)

生徒や実演者の機械で動く道具 (Ergo Studio の「授業」プラグイン。Ergo 側の仕様は Ergo `spec/feature/tool/lesson.md`) が、
授業と HTTP でやり取りする。道具は HTTP しか持たなくてよい (WebSocket は使わない)。

**つなぎ方。** 生徒はページの「接続文字列を出す」、操作者は操作卓の「実演用の道具をつなぐ」を押す。10 文字の接続コード
(120 秒有効・1 回だけ・出し直すと前のコードは無効) が出るので、`<授業の origin>/v1/tool#<コード>` の形で道具に貼り付ける。
道具はコードをトークンに引き換える。トークンは「その授業のその生徒 (または実演者)」だけを表し、1 人につき 2 台まで
(3 台目は最も古いものと入れ替わる)。退出・授業を閉じる・プロセス終了で無効になる。コードもトークンも保存せず、ログにも出さない。
間違ったコードはサービス全体で 1 分 30 回まで。

| 経路 (生徒側の待受) | 内容 |
| --- | --- |
| `POST /v1/tool/pair` `{link, tool}` | → `{token, role: student \| presenter, class: {title}, poll_ms}`。`link_not_found` (404) / `rate_limited` (429) |
| `GET /v1/tool/state` (`Authorization: Bearer`) | → `{role, class, features, assignment, demo}`。無効なトークンは `tool_unlinked` (401) |
| `POST /v1/tool/progress` `{assignment_id, step, done: true}` | 生徒の道具だけ。`not_assigned` (409) / `forbidden_role` (403)。`done: false` は受け付けない |

- POST は `Content-Type: application/json`、本文 4 KiB まで (JSON は値 64 個・入れ子 4 段まで。超えたら `invalid_request` (400))。Host / Origin の検査は他の経路と同じ (別サイトからは呼べない)。
- `features`: 実演の名前 → ゲームの bool 変数名 (プロットの `tool.features`)。
- `assignment` (生徒): 出ている課題の手順と、その生徒の済み・未済み。`check` (`{variable, op, value}`、`op` は
  `gt` `ge` `lt` `le` `eq` `ne`) の付いた手順は、道具がゲームの変数を見て満たしたときに `progress` を送る。一度付けたチェックを道具は外さない。
- `demo` (実演者): `{seq, states}`。`states` はタイムラインがここまでに切り替えた実演の ON / OFF、`seq` は切替のたびに増える。
  `feature: "all"` は `tool.features` の全部を切り替える。位置の移動 (seek / 次のセクションへ) をしたときは、飛ばした切替も
  反映した状態に作り直す。道具は `states` に合わせて変数を設定する。
- 操作卓の生徒一覧には道具をつないだ生徒に「道具」が付き、実演用の道具の接続有無も出る。
- **つながったことを生徒に伝える。** 道具が生徒の接続コードを引き換えると、その生徒のページに `tool.linked`
  (`tools`: つないだ道具の名前の列、`count`) を送る。名前は道具が `pair` の `tool` で名乗ったもので、英数字・空白・`. _ - + ( )` だけを
  残して 40 文字まで (空なら「名前の無い道具」) にする。ページは残り時間の表示をやめ、「道具がつながりました: <名前>」を出し続ける。
  入り直したページには `welcome` の後に同じものを送る。生徒はページの「道具の接続を切る」(`tool.unlink`) で自分の道具を切れ、
  そのときは `tool.unlinked` (`reason: "student"`) を返す (道具は次の問い合わせで `tool_unlinked`)。`/v1/tool/*` の形は変えていない。

サンプル教材は `feel.hit_stop` / `feel.knockback` / `feel.camera_shake` (実演) と、`feel.hit_stop_last_seconds > 0` /
`feel.knockback_last_impulse > 0` (課題の自動確認) を使う。これらを公開するのは Ergo の**ヘッドレスのサンプル**
`examples/lesson_action_feel` (Ergo ブランチ `claude/ai-lesson-odeum-j57vy6`、LUDIARS/Ergo#95。仕様は Ergo
`spec/feature/tool/lesson.md` の「サンプル」)。プレイヤーが世界時間 0.5 秒ごとに敵を叩き続ける決まったシミュレーションで、
`--plain` で演出 3 つを OFF にして始まる。`..._last_*` は実際に止めた秒数 (0.08)・与えた撃力 (6) で、OFF に戻しても残る。
2 秒ごとにログ (`world=` `hits=` `hit_stop_last_seconds=` `knockback_last_impulse=` `enemy_offset=` `shake=`) を出す。
**遊べる Ergo 版のアクションゲーム (ActionGameSample の移植) はまだ無い。** 教材の課題は、Studio と授業をつなぎ
(「授業」タブ、窓の無い Studio は `POST /lesson/api/connect`)、Studio の `/variable/ws` に `set` を送って演出を ON に戻し、
ログの数値の変化を確かめる形にしてある (Studio には変数を切り替える画面がまだ無い)。Ergo 側の記録では、この組み合わせで
`add-hitstop` / `add-knockback` の自動チェックが授業に届くことを Linux (libcurl 版) で確かめている。

## 生徒の声の聞き分け

- **一人一台**: 声は生徒ごとの接続で届くので、誰の声かは接続で決まる。端末は音量 (0–100) だけを送り、
  サーバが「話し中」を判定する (700ms 以内の間は同じ発話)。複数人が同時に話しても、それぞれ別に扱う。
- **発話の中身**: 既定では生徒が文字で送る。`ODEUM_LESSON_BROWSER_STT=1` のときだけブラウザの音声認識を使う
  (ブラウザによっては音声がブラウザ提供元へ送られるため、既定は無効)。サーバ側の音声認識はモデル到着後。
- **教室にマイクが 1 本**: 外部の話者分離が付けた話者ラベルを `voice.diarized` で受ける。生徒は自分の端末に出た
  3 桁の番号を読み上げて、自分のラベルを登録する (60 秒有効)。未登録のラベルの声は操作者にだけ見せる。
- 発話はモデルが読み取り、質問 → 個別に回答、助けて → ヒント、問いが開いていれば回答として受け取る、
  ふざけ → 素行の記録、に振り分ける。読み取り結果は操作卓に出す。

## ふざけた生徒の発言停止と退出

| 出来事 | 点 |
| --- | --- |
| 中身のない連投 (同じ文字 6 連続、記号だけ) | 1 |
| 暴言 | 2 |
| 10 秒に 9 件以上の投稿 | 1 (連投 1 回につき) |
| 授業と関係ない発言が 1 分に 4 回 | 1 |

点は 10 分で消える。初回は注意、3 点で発言停止 (60 秒、次は倍、最長 15 分)、6 点または 3 回目の発言停止で退出。
発言停止中は授業を見ること・課題・ヒントの要求はできるが、回答・質問・発話はできず、「話し中」にも出ない。
退出は接続を切り、その授業が終わるまで戻れない。同時に入室を締め切る (別名での入り直しを防ぐ。操作者が解除できる)。
操作者は手動で発言停止・解除・退出・復帰ができる。黙っている生徒が罰を受けることはない。

## 良い質問の共有

質問には必ず本人だけに答えを返す。似た質問 (文字 2-gram の一致 0.6 以上) は 1 件にまとめ「私も知りたい」に数える
(同じ人が同じ質問を出し直したときは数えない)。「私も知りたい」は質問した本人には出さず、本人の投票は `own_question` で断る。
数はサーバが送ったもの (`question.votes`、全員へ) だけを出し、押した人には `question.voted` を返す。
モデルの評価 70 点以上で、答えを用意できた質問だけが自動共有の対象 (1 回に 2 件まで)。
共有は名前を付けない (本人が選んだときだけ名前を出す)。

**自分の質問の行方。** 質問した生徒 (と「私も知りたい」を押した生徒) のページには「あなたの質問」の一覧があり、サーバが送る
状態 (`question.status`、`welcome` の `my_questions`) を出す: `answered` (答えあり、用意した答え) / `waiting` (先生の回答待ち) /
`teacher` (先生から回答) / `dismissed` (見送り)。操作者が見送ったときは、本人と「私も知りたい」の人に「この授業の中では答えが届かない」と
そのまま伝え、共有済みなら全員の一覧から外す (`question.removed`)。

**規則で言えることだけを言う。** 規則で分かるのは「用意した答えがある」「同じことを N 人が知りたがった」までで、その答えで疑問が
解けたかは分からない。質問した本人は、受け取った答えに「まだ分からない」(`question.unresolved {id}`) を返せる。その質問は先生の
回答待ちに戻り、自動共有の対象から外れ、操作卓に `attention` (`question_unresolved`) が出る (本人以外は `not_your_question`、すでに
回答待ちなら `no_answer_yet`)。自動で共有したときの本人への文は「答えが用意してあり、規則による評価 (質問の言葉と、知りたい人 N 人) が
基準を超えたため。疑問が解けたかはこの判定では分からない」で、褒めない。共有された質問は答えの出どころ (`answer_from`: `prepared` /
`teacher` / `none`) を持つ。

**答えを用意できない質問** は、本人に「用意した答えがありません。人間の先生に回しました。先生から直接答えが届くことがあり、
届いたらここに出ます」と返し (授業で取り上げるとは約束しない)、操作者に `attention` (`question_needs_teacher`) を出す。
操作卓の質問一覧では、答えるか見送るまで「先生の回答待ち」として一番上に残り、回答欄がある。操作者の回答
(`questions.answer {id, text}`) は、質問した本人と「私も知りたい」の人に、その質問への答え (`reply`、`question_id`・`from: "teacher"`)
として届き、以後その質問は答えのある質問として共有できる (共有済みなら全員の表示も更新する)。
操作者はどの質問も手動で共有・見送りにできる。

**後の問いの答えに触れる用意した答え** (FAQ の `after`) は、その問いの結果を見せるまで使わない。いちばん当てはまる答えが
それなら、質問は答えを用意できない質問と同じに人間の先生へ回し、本人には「用意した答えは、このあとの授業の問いの答えに触れるため、
いまは出せない」と返す (別の、当てはまりの弱い答えで代えない)。サンプル教材では、ヒットストップの長さ・何を止めるか・重なり・
カメラの揺れ・Ergo の hit_stop の答えが `hitstop-design`、ノックバックの向き・地形と、ダメージと威力の違いの答えが
`knockback-effects`、敵の配置の答えが `enemy-placement` を待つ (3 回目の出席で、ヒットストップの長さの答えの「威力 ÷ 24 秒」が
その後の `weapon-power` の答えを明かしていた)。単体テスト (`lesson_faq_tests`) が、どの FAQ の答えも、規則で採点すると後の問いの
正解になる、またはその問いの解説・模範解答と 10 文字以上 (うち 5 文字以上が非 ASCII) 同じ、のどちらかなら、その問い以降を `after` に
持つことを確かめる。

**授業の終わり。** `lesson.end` の時点で先生の回答待ちの質問がある生徒 (質問した人と「私も知りたい」の人) には、その質問を挙げて
「授業の時間内に答えが届かなかった」と一度だけ伝える (`reply` の `about: "questions_unanswered"`)。操作卓は先生の回答待ちの数
(`snapshot` の `questions_waiting`) を常に目立つ帯で出し、「授業を閉じる」の確認にもその数を出す。

## API

生徒側 (`ODEUM_LESSON_BIND`:`ODEUM_LESSON_PORT`):

- `GET /health` → `{ok:true,version}`
- `GET /lesson`, `GET /web/*` — 埋め込みページ
- `GET /v1/prep.pptx?plot=<id>` — 予習シート
- `POST /v1/tool/pair`, `GET /v1/tool/state`, `POST /v1/tool/progress` — 道具 (上の「道具との連携」)
- `GET /v1/join?code=&name=[&resume=]` — WebSocket。拒否理由は upgrade 後に `error` で返す
  (`class_not_found` / `rate_limited` / `invalid_name` / `entry_locked` / `ejected` / `capacity`)

操作卓 (`127.0.0.1`:`ODEUM_LESSON_CONSOLE_PORT` 固定):

- `GET /console`, `GET /web/*`, `GET /v1/prep.pptx`, `GET /health`
- `GET /v1/console?token=` — WebSocket

メッセージは JSON、受信は 16 KiB まで (値 1024 個・入れ子 8 段まで。relay と同じ。超えたら `invalid_message`)、毎秒 120 件を超えたら切断。種類と項目は
`native/lesson/core/classroom.cpp` (受信) と `classroom_cues.cpp` / `classroom_views.cpp` (送信) が正本。

## 操作卓の保護

操作卓は開講・発言停止・退出を行えるので、この機械を直接操作している人だけが使える。

1. 待受は `127.0.0.1` 固定 (設定で変えられない)。
2. `Forwarded` / `X-Forwarded-*` / `X-Real-IP` / `CF-Connecting-IP` の付いた要求は拒否 (転送経路は接続元が loopback に見えるため)。
3. `Host` は `127.0.0.1` / `localhost` / `[::1]` + 操作卓のポート、`Origin` は同じ origin、`Sec-Fetch-Site` が cross-site / same-site なら拒否。
4. WebSocket は起動のたびに作り直すトークンが要る。トークンは `ODEUM_LESSON_CONSOLE_TOKEN_FILE` に所有者だけが読める権限で書く
   (Windows はファイルを置くフォルダの ACL に従う)。ページは `/console#token=<値>` で開き、読み取った後に URL から消す。
5. 操作は種類・授業 id・生徒 id・結果だけを標準エラーに記録する (名前と本文は記録しない)。

**転送経路 (Cloudflare Tunnel 等) の転送先に操作卓のポートを登録しないこと。**

## 設定

| 環境変数 | 既定・形式 |
| --- | --- |
| ODEUM_LESSON_CONSOLE_TOKEN_FILE | 必須。操作卓トークンを書くファイル |
| ODEUM_LESSON_BIND | 127.0.0.1、IP literal |
| ODEUM_LESSON_PORT | 4410、1–65535 |
| ODEUM_LESSON_CONSOLE_PORT | 4411、1–65535、`ODEUM_LESSON_PORT` と別 |
| ODEUM_LESSON_MAX_STUDENTS | 60、1–300 (1 授業あたり) |
| ODEUM_LESSON_PLOT | 任意。追加するプロットの JSON ファイル |
| ODEUM_LESSON_BROWSER_STT | 0。1 でブラウザの音声認識を使う |
| ODEUM_LESSON_PUBLIC_URL / ODEUM_LESSON_ALLOWED_ORIGINS / LUDIARS_ALLOWED_HOSTS | relay の同名設定と同じ規則 (`WebAccess`) |

明示された空値・不正値は起動失敗。同時に開ける授業は 8 件。参加コードは Crockford base32 の 10 文字で、
間違ったコードはサービス全体で 1 分 30 回まで。

## セクションが変わるとき

セクションの始まりで、前のセクションの問い (結果を含む)・スライド・語りは片付ける。ページは題を変えると同時に、実演の表示・
スライド・語り・問いの欄を消し、新しいスライドと最初の語りを待つ。途中から入った生徒にも前のセクションの結果は出ない。
課題は出ている間は残る。

## 生徒のページの「先生からあなたへ」

個別のヒント・質問の答え・先生からの一言は「先生からあなたへ」に届く。一覧は `aria-live="polite"` の領域で、さらに一覧が
画面に見えていないときは、画面下に「先生からあなたへ 新着 N 件: <冒頭>」の知らせを出す (フォーカスは動かさない。押すと一覧へ
移り、一覧が見えたら消える)。知らせが出ている間は、ページの最後の操作 (共有された質問の「私も知りたい」) が知らせの上まで
スクロールできるよう、知らせの高さだけ下に余白を取る。各操作の確かめの表示 (トースト) は、その操作でサーバが実際にしたことだけを言う
(「まだ分からない」→ 先生の回答待ちに戻した、「私も知りたい」→ 受け付けた、「質問する」→ 送った)。

## 個人データ

表示名・回答・質問・発話は授業が動いている間だけメモリに持ち、ファイルにも DB にも書かない。授業を閉じるかプロセスを
終えると消える。音声そのものはサーバに送らない (音量の数値だけ)。ログに名前と本文を出さない。

## ビルドと検証

`cmake -S native -B native/build && cmake --build native/build` で `native/build/bin/odeum-lesson`。
`ODEUM_BUILD_LESSON=OFF` で外せる。テストは `ctest --test-dir native/build -R lesson` (`native/tests/lesson_*_tests.cpp`)。

確認済み (2026-11-11、Linux / GCC 13): 単体テスト 16 本 (欠陥の修正分を含む)、道具の HTTP 経路 (接続コードの発行と引き換え、状態の取得、進み具合の報告、
拒否の各種、退出・閉講での失効) とページの表示、CLI での pptx 生成 (python-pptx で 13 枚として開ける、
LibreOffice で描画)、ブラウザでの通し (操作卓 1 + 生徒 2: 開講 → 問い → 結果 → 課題とヒント → 質問共有 → 発言停止 → 退出 → 入り直し拒否)。

授業の評価用に、AI エージェントを生徒の 1 席として出席させ、出席者の画面と操作卓を 1 本の動画に録るハーネスがある
(`native/lesson/tools/attend/`、使い方は同フォルダの `README.md`)。`classroom.cjs` が操作卓の本物の操作 (「次のセクションへ」と「この合図まで進める」で、問い・課題・実演はタイムライン自身が出す)
で 90 分の授業を約 17 分に縮めて進め (記述の問いは 90 秒、選択は 60 秒、共有の後に 45 秒)、出席者は `seat.cjs` (observe / wait / answer / tick / help / ask / say / vote / tool-link /
unresolved / status) で参加する。`--teacher-answers` で、作者が用意した答えを操作卓の回答欄から返し、「見えない・聞こえない」の
知らせを「確認した」で受ける「人間の先生」役を付けられる。台本の級友は画面がいま出している操作だけを試し、もう出ていない操作は
飛ばして記録する (画面が出しているのに通らなければ止まる)。
`smoke.cjs` がハーネス自体の通し確認。動画とログは指定した作業フォルダに出る試験成果物で、リポジトリには入れない。

## 外から入る入力の上限 {#SPEC-ODEUM-LESSON-INPUT-LIMITS}

正本は `native/lesson/input_limits.hpp`。JSON は Lorica の `input_budget` (`odeum::parse_json_within`) で、バイト数・値の数・入れ子を
読みながら数え、超えた時点で断る (job cpp-lorica-20261111)。

| 入力 | 上限 | 断ったとき |
| --- | --- | --- |
| WebSocket のメッセージ (生徒・操作卓) | 16 KiB、値 1024、深さ 8 | `invalid_message` を返し、接続は続く |
| HTTP の要求 | ヘッダ 16 KiB、本文 4 KiB (Beast のパーサ)、10 秒 | 接続を閉じる |
| 道具の POST 本文 | 4 KiB、値 64、深さ 4 (正しい本文は値 7 個) | `invalid_request` (400) |
| プロットのファイル (`ODEUM_LESSON_PLOT`、`timeline` / `prep-sheet` の引数) | 1 MiB (1 MiB + 1 バイトで読むのをやめる)、値 16384、深さ 16 | `invalid_plot` で起動・コマンドが止まる |

組み込みの教材 (90 分) は値 1,223 個・深さ 7 で、プロットの上限の 10 分の 1 未満。
